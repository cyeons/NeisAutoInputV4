# 행동발달 기능 현행 개발 계획

## 1. 문서 목적

이 문서는 현재 구현된 행동특성 및 종합의견 기능의 동작을 현행 사양으로 정의한다.
초기 설계 이후 변경된 문장 수·검증·적용 방식은 현재 프로그램의 동작을 기준으로 정리한다.

## 2. 화면과 데이터 흐름

- 사이드바에 `행동발달` 전용 화면을 제공한다.
- 화면은 학생 명단, 특성 선택, 선택 특성 및 생성 결과의 3단 패널로 구성한다.
- 학생 명단은 `StudentRoster`를 통해 자동 입력 화면과 실시간 공유한다.
- 학생 이름은 화면 표시와 로컬 저장에만 사용하고 AI 요청에는 UUID만 포함한다.
- 학생별 특성, 문장 수 재정의, 초안, 생성 상태를 `hb_work.json`에 저장한다.
- 생성 초안은 UUID 기준으로 자동 입력 화면의 해당 학생에게 적용한다.

## 3. 학생 명단

- 각 학생은 실행 중 안정적인 UUID를 가진다.
- CSV 형식은 기존 호환성을 위해 `이름,내용` 두 열을 유지한다.
- 프로그램 시작 시 `hb_work.json`의 행 위치와 이름을 이용해 기존 UUID를 재연결한다.
- 이름·내용·학생 수 변경은 공유 명단을 통해 두 화면에 반영한다.
- 특성 또는 초안이 있는 학생을 학생 수 축소로 삭제할 때 확인 창을 표시한다.
- 행동발달 학생 목록에는 이름, 선택 특성 수와 상태 배지를 표시한다.
- 검색과 전체·생성 가능·완료·실패 필터를 제공한다.

## 4. 특성 카탈로그

### 4.1 교과 특성

- 국어
- 수학
- 사회
- 과학
- 영어
- 도덕
- 체육
- 음악
- 미술
- 기타

실과와 통합교과에 해당하는 일반 특성은 `기타`에서 제공한다.
학년별 교과 필터는 사용하지 않는다.

### 4.2 인성·행동·태도 특성

- 자신감·자기표현
- 성실·책임
- 배려·존중
- 협력·공동체
- 의사소통
- 자기관리
- 끈기·도전
- 리더십·참여
- 관계·적응
- 변화·성장

기본 카탈로그는 `resources/behavior_traits.json`에서 불러온다.

### 4.3 특성 단계

각 특성은 다음 단계 중 하나로 선택한다.

- 강점: 특성이 뚜렷하거나 지속적으로 관찰됨
- 일반: 특성이 관찰됨
- 성장 필요: 관련한 연습이나 지원이 필요함

단계는 특성 버튼과 선택 목록의 색상으로 구분한다.
선택한 단계는 같은 특성을 다시 눌러 변경할 수 있다.

### 4.4 사용자 특성

- 현재 선택한 그룹과 카테고리에 짧은 사용자 특성을 추가한다.
- 같은 카테고리 안의 중복 이름은 허용하지 않는다.
- 사용자 특성은 `hb_custom_traits.json`에 저장하여 다른 작업에서도 재사용한다.
- 사용자 특성을 카탈로그에서 삭제해도 기존 학생 작업의 ID와 라벨 스냅샷은 유지한다.

## 5. 문장 수

- 전체 기본 문장 수는 1~8 범위에서 설정한다.
- 현재 기본값은 저장된 작업과 환경 설정을 우선하며 초기값은 3문장이다.
- 학생마다 1~8 범위에서 개별 문장 수를 재정의할 수 있다.
- 재설정 버튼을 누르면 해당 학생은 전체 기본 문장 수를 사용한다.
- 문장 수가 1개이면 선택 특성 중 하나를 임의로 필수 반영 대상으로 지정하고 나머지는 제외 대상으로 요청한다.

## 6. 생성 프롬프트

### 6.1 기본 원칙

- 초등학교 담임교사의 객관적인 현재 관찰 기록 문체를 사용한다.
- 학생 이름이나 학생을 직접 지칭하는 주어를 넣지 않는다.
- 현재형 명사형 종결을 사용한다.
- 과거형, 쉼표, 번호, 소제목, 따옴표, 괄호와 불릿을 사용하지 않도록 요청한다.
- 과장·감상·학생 간 비교·낙인·민감정보 추측을 피한다.
- 입력에 없는 사건·직책·날짜·빈도·장소·성적·관계·수상 내용을 만들지 않도록 요청한다.
- 강점과 성장 필요 특성을 우선하여 핵심 특성을 자연스럽게 연결한다.
- 최근 생성 결과를 함께 전달하여 도입부와 표현의 반복을 줄인다.

### 6.2 출력 목표

- 학생별 요청 문장 수를 맞춘 하나의 문단을 생성한다.
- 프롬프트상 목표 길이는 공백 포함 250~280자이다.
- 출력은 학생별 구조화 객체 배열로 받는다.
- 각 객체에는 학생 UUID, 문단, 사용 특성 ID, 제외 특성 ID와 모델이 계산한 지표를 포함한다.

길이와 문체 조건은 AI 생성 지침이다.
현재 프로그램은 생성 결과를 강제로 차단하는 규칙 기반 validator를 사용하지 않는다.
화면에는 로컬에서 다시 계산한 글자 수, UTF-8 byte 수와 문장 수를 정보로 표시한다.

## 7. 구조화 출력과 응답 처리

공급자가 지원하면 JSON Schema를 사용하여 다음 필드를 요청한다.

```text
results[]
- student_id
- comment
- used_trait_ids
- omitted_trait_ids
- character_count
- utf8_byte_count
- sentence_count
```

- JSON Schema가 지원되지 않으면 JSON 응답 모드로 다시 요청한다.
- 응답에 요청 학생 UUID가 없거나 문단이 비어 있으면 해당 학생을 실패 처리한다.
- 결과 매핑에는 학생 이름이나 표시 순서를 사용하지 않고 UUID를 사용한다.
- 모델이 반환한 지표 대신 프로그램이 NFC 정규화된 문단에서 지표를 다시 계산한다.
- 비어 있지 않은 문단은 생성 완료 상태로 저장하며 교사가 직접 편집할 수 있다.
- 교사가 편집한 비어 있지 않은 초안도 완료 상태로 취급한다.

## 8. 생성 범위와 오류 처리

### 8.1 현재 학생 생성

- 현재 선택한 학생에게 특성이 하나 이상 있을 때 생성한다.
- 특성이 없으면 API를 호출하지 않고 안내한다.

### 8.2 전체 생성

- 특성이 하나 이상 선택된 모든 학생을 대상으로 한다.
- 특성이 없는 학생은 요청에서 제외한다.
- 최대 10명 단위의 묶음으로 순차 요청한다.
- 앞 묶음의 성공 결과를 다음 묶음의 중복 방지 참고로 사용한다.
- 일부 묶음이 실패해도 성공한 묶음의 결과는 보존한다.

### 8.3 재시도

- 429, 5xx, timeout, unavailable 등 일시적인 공급자 오류만 재시도한다.
- 최초 요청 이후 최대 두 번 재시도하며 대기 시간은 단계적으로 늘린다.
- 출력 형식이나 길이 조건에 대한 별도 자동 보정 요청은 수행하지 않는다.

## 9. 결과 편집과 적용

- 생성 문단은 학생별 편집기에서 직접 수정할 수 있다.
- 편집 중 글자 수, UTF-8 byte 수와 문장 수를 실시간으로 갱신한다.
- 초안이 있는 모든 현재 학생을 `생성 결과 적용` 대상으로 삼는다.
- 적용 대상의 NEIS 내용이 이미 있으면 학생 이름 목록을 보여 주고 덮어쓰기 확인을 받는다.
- 확인 후 UUID가 일치하는 자동 입력 표의 내용만 변경한다.
- 별도의 학생별 적용 체크박스나 `needs_review` 적용 차단 상태는 사용하지 않는다.

## 10. 저장

`hb_work.json`의 현행 주요 구조:

```json
{
  "schema_version": 3,
  "default_sentence_count": 3,
  "students": [
    {
      "student_id": "uuid",
      "name_snapshot": "학생 이름",
      "sentence_count_override": null,
      "traits": [
        {
          "trait_id": "behavior.responsibility",
          "level": "strength",
          "label_snapshot": "책임감"
        }
      ],
      "draft": "",
      "status": "not_generated",
      "error_message": "",
      "used_trait_ids": [],
      "omitted_trait_ids": []
    }
  ]
}
```

- 지원 상태는 `not_generated`, `generating`, `ok`, `failed`이다.
- 특성, 단계, 문장 수, 초안과 명단이 바뀌면 약 450ms debounce 후 자동 저장한다.
- `작업 저장` 버튼은 행동발달 JSON과 학생 CSV를 함께 저장한다.
- JSON과 CSV는 임시 파일 작성 후 교체하는 방식으로 저장한다.
- 이전 행동발달 작업 스키마는 로드 시 현행 기본 문장 수 규칙에 맞춰 변환한다.

## 11. 공급자와 설정

- Gemini와 OpenAI를 지원한다.
- API 키가 등록된 공급자만 선택할 수 있다.
- API 키는 교과 평어와 같은 keyring 보안 저장소를 공유한다.
- 행동발달 공급자와 모델 설정은 교과 평어 설정과 별도로 저장한다.
- 모델은 프로그램이 제공하는 지원 모델 목록에서 선택한다.

## 12. 코드 구조

- `resources/behavior_traits.json`: 기본 특성 카탈로그
- `neis_v4/models.py`: 행동발달 작업·요청·결과 모델
- `neis_v4/roster.py`: 화면 간 공유 학생 명단
- `neis_v4/behavior_catalog.py`: 기본·사용자 특성 관리
- `neis_v4/storage.py`: 행동발달 작업과 사용자 특성 저장
- `neis_v4/ai/behavior_prompt.py`: 시스템 프롬프트와 JSON Schema
- `neis_v4/ai/behavior_response.py`: JSON 파싱·UUID 매핑·지표 계산
- `neis_v4/ai/gemini_provider.py`: Gemini 구조화 생성
- `neis_v4/ai/openai_provider.py`: OpenAI 구조화 생성
- `neis_v4/ui/behavior_tab.py`: 특성 선택·생성·편집·적용 UI
- `neis_v4/ui/main_window.py`: 자동 입력 화면과 행동발달 화면 연결

## 13. 현재 자동 테스트

- 기본 특성 ID 고유성과 카테고리 구성
- 사용자 특성 저장과 복구
- 학생 이름이 AI 요청에 포함되지 않는지 확인
- 구조화 결과의 UUID 매핑과 로컬 지표 계산
- 누락되거나 빈 결과의 실패 처리
- 행동발달 작업 저장과 UUID 재연결
- 이전 스키마의 기본 문장 수 마이그레이션
- 특성 선택과 단계 변경
- 1문장 생성 시 반영 특성 선택
- 생성 실패 시 기존 초안 보존
- 생성 초안의 UUID 기준 NEIS 적용
- 10명 단위 묶음의 부분 성공 보존
- 일시적인 공급자 오류 재시도

실행 명령:

```powershell
python -m unittest discover -s tests -v
```
